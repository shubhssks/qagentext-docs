# Security And Sensitive Reports

Do not post an exploit involving private data, credentials, session artifacts,
customer systems or non-public extension details in a public issue.

Use the developer contact shown on the
[official Chrome Web Store listing](https://chromewebstore.google.com/detail/qagentext-qa-testing-agen/fmabdhbonhmnomjogiehbhadalondhch)
to request a private reporting channel. Send a short non-sensitive summary first;
do not send secrets or a full browser profile by email. No response-time or bug
bounty commitment is implied.

For an ordinary reproducible bug with dummy data, use the bug-report template
after the repository is published. Review screenshots and diagnostic exports
before attaching them. If you accidentally expose a credential, revoke it through
the owning service; deleting a public attachment alone does not undo exposure.

This repository contains documentation and independent examples, not the private
extension implementation or an extension distribution package.
